# การแฮช

`HashSet` และ `HashMap` เป็นชนิดข้อมูลสองตัวที่นิยมใช้งานกันอย่างแพร่หลาย และมีเทคนิคหลากหลายวิธีในการเพิ่มความเร็วให้กับพวกมัน

## ตัวแฮชทางเลือก

อัลกอริทึมการแฮชเริ่มต้น (default hasher) ของ Rust ไม่ได้ถูกระบุไว้เป็นข้อกำหนดตายตัว แต่ ณ เวลาที่เขียนหนังสือเล่มนี้ ค่าเริ่มต้นคืออัลกอริทึม [SipHash 1-3] อัลกอริทึมนี้มีคุณภาพสูงมาก—สามารถป้องกันการชนกันของค่าแฮช (hash collision) ได้เป็นอย่างดี—แต่ค่อนข้างช้า โดยเฉพาะอย่างยิ่งเมื่อใช้กับคีย์ขนาดสั้น เช่น จำนวนเต็ม (integer)

[SipHash 1-3]: https://en.wikipedia.org/wiki/SipHash

หากผลการทำ profiling บ่งชี้ว่าการแฮชเป็นคอขวดที่ทำงานหนัก (hot path) และ [การโจมตี HashDoS] ไม่ใช่เรื่องที่ต้องกังวลสำหรับแอปพลิเคชันของคุณ การเปลี่ยนมาใช้ hash table ที่ใช้อัลกอริทึมแฮชที่เร็วกว่าก็สามารถเพิ่มความเร็วในการทำงานได้อย่างก้าวกระโดด:
- [`rustc-hash`] มาพร้อมกับชนิดข้อมูล `FxHashSet` และ `FxHashMap` ซึ่งสามารถนำมาใช้งานแทน `HashSet` และ `HashMap` ได้ทันที (drop-in replacement) อัลกอริทึมแฮชของมันแม้จะมีความสุ่มต่ำกว่า แต่ทำงานได้รวดเร็วมาก โดยเฉพาะกับคีย์ที่เป็นจำนวนเต็ม และพบว่ามีประสิทธิภาพเหนือกว่าอัลกอริทึมแฮชอื่นๆ ทั้งหมดเมื่อนำมาใช้ภายในคอมไพเลอร์ rustc (ทั้งนี้ crate [`fxhash`] คือ implementation ที่เก่ากว่าและไม่ค่อยได้รับการดูแลแล้วของอัลกอริทึมและชนิดข้อมูลชุดเดียวกัน)
- [`fnv`] มาพร้อมกับชนิดข้อมูล `FnvHashSet` และ `FnvHashMap` อัลกอริทึมแฮชของมันมีคุณภาพสูงกว่า `rustc-hash` เล็กน้อย แต่ความเร็วจะช้ากว่า
- [`ahash`] มี `AHashSet` และ `AHashMap` โดยอัลกอริทึมแฮชของมันสามารถดึงความสามารถของชุดคำสั่ง AES hardware acceleration ที่มีอยู่ใน CPU บางรุ่นมาช่วยเพิ่มประสิทธิภาพได้

[การโจมตี HashDoS]: https://en.wikipedia.org/wiki/Collision_attack
[`rustc-hash`]: https://crates.io/crates/rustc-hash
[`fxhash`]: https://crates.io/crates/fxhash
[`fnv`]: https://crates.io/crates/fnv
[`ahash`]: https://crates.io/crates/ahash

หากประสิทธิภาพการแฮชมีความสำคัญในโปรแกรมของคุณ การลองเปรียบเทียบทางเลือกมากกว่าหนึ่งตัวย่อมคุ้มค่า ตัวอย่างเช่น ผลลัพธ์จากการทดสอบจริงในตัวคอมไพเลอร์ rustc พบว่า:
- การเปลี่ยนจาก `fnv` มาเป็น `fxhash` ช่วย [เพิ่มความเร็วขึ้นได้ถึง 6%][fnv2fx]
- แต่ความพยายามที่จะเปลี่ยนจาก `fxhash` ไปเป็น `ahash` กลับส่งผลให้ [ช้าลง 1-4%][fx2a]
- และความพยายามที่จะเปลี่ยนจาก `fxhash` กลับไปใช้ตัวแฮชเริ่มต้น กลับส่งผลให้ [ช้าลงตั้งแต่ 4-84%][fx2default] เลยทีเดียว!

[fnv2fx]: https://github.com/rust-lang/rust/pull/37229/commits/00e48affde2d349e3b3bfbd3d0f6afb5d76282a7
[fx2a]: https://github.com/rust-lang/rust/issues/69153#issuecomment-589504301
[fx2default]: https://github.com/rust-lang/rust/issues/69153#issuecomment-589338446

หากคุณตัดสินใจนำทางเลือกใดทางเลือกหนึ่งมาใช้ทั่วทั้งโปรเจกต์ เช่น `FxHashSet`/`FxHashMap` ก็เป็นไปได้ง่ายมากที่จะเผลอกลับไปใช้ `HashSet`/`HashMap` ในบางจุดโดยไม่ได้ตั้งใจ ซึ่งคุณสามารถ [ใช้ Clippy] เพื่อช่วยป้องกันปัญหานี้ได้

[ใช้ Clippy]: linting.md#การหามใชชนิดขอมูล

ชนิดข้อมูลบางชนิดไม่จำเป็นต้องผ่านการแฮชด้วยซ้ำ ตัวอย่างเช่น หากคุณมี newtype ที่ห่อหุ้มค่าจำนวนเต็มเอาไว้ และค่าจำนวนเต็มนั้นเป็นค่าสุ่มหรือมีลักษณะกระจายตัวใกล้เคียงกับค่าสุ่มอยู่แล้ว การกระจายตัวของค่าแฮชก็คงไม่ต่างจากการกระจายตัวของค่าตัวมันเองเท่าใดนัก ในกรณีนี้ crate [`nohash_hasher`] จะมีประโยชน์อย่างมาก

[`nohash_hasher`]: https://crates.io/crates/nohash-hasher

การออกแบบฟังก์ชันแฮชเป็นหัวข้อที่ลึกซึ้ง ซับซ้อน และอยู่นอกเหนือขอบเขตของหนังสือเล่มนี้ หากสนใจสามารถอ่านคำอธิบายที่ดีเยี่ยมได้ใน [เอกสารของ `ahash`]

[เอกสารของ `ahash`]: https://github.com/tkaitchuck/aHash/blob/master/compare/readme.md

## การแฮชแบบรายไบต์

เมื่อคุณกำกับชนิดข้อมูลด้วย `#[derive(Hash)]` เมธอด `hash` ที่ถูกสร้างขึ้นมาจะทำการแฮชแต่ละฟิลด์แยกกัน แต่สำหรับฟังก์ชันแฮชบางตัว การแปลงข้อมูลทั้งก้อนเป็นไบต์ดิบ (raw bytes) แล้วแฮชสตรีมของไบต์เหล่านั้นไปในคราวเดียวอาจทำงานได้เร็วกว่า ซึ่งวิธีนี้จะใช้ได้กับชนิดข้อมูลที่มีคุณสมบัติตรงตามเงื่อนไขบางประการ เช่น ต้องไม่มี padding byte อยู่ภายในโครงสร้างข้อมูล

crate [`zerocopy`] และ [`bytemuck`] ต่างก็มีมาโคร `#[derive(ByteHash)]` ที่สร้างเมธอด `hash` สำหรับการแฮชแบบรายไบต์ลักษณะนี้ขึ้นมาให้ และใน README ของ crate [`derive_hash_fast`] ก็ได้อธิบายรายละเอียดเชิงลึกของเทคนิคนี้เอาไว้อย่างดี

[`zerocopy`]: https://crates.io/crates/zerocopy
[`bytemuck`]: https://crates.io/crates/bytemuck
[`derive_hash_fast`]: https://crates.io/crates/derive_hash_fast

นี่เป็นเทคนิคขั้นสูง และผลลัพธ์ด้านประสิทธิภาพจะขึ้นอยู่กับทั้งฟังก์ชันแฮชและโครงสร้างของชนิดข้อมูลที่นำมาแฮชอย่างมาก จึงควรวัดผลด้วยความระมัดระวังเสมอ
