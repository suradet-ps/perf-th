# การทำเบนช์มาร์ก

การทำเบนช์มาร์ก (benchmarking) มักเป็นการเปรียบเทียบประสิทธิภาพของโปรแกรมตั้งแต่สองโปรแกรมขึ้นไปที่ทำงานอย่างเดียวกัน บางครั้งอาจเป็นการเปรียบเทียบโปรแกรมที่แตกต่างกันตั้งแต่สองโปรแกรม เช่น Firefox กับ Safari กับ Chrome และบางครั้งเป็นการเปรียบเทียบโปรแกรมเดียวกันสองเวอร์ชัน ซึ่งกรณีหลังนี้ช่วยให้เราตอบคำถามที่ว่า "การเปลี่ยนแปลงนี้ทำให้เร็วขึ้นหรือไม่" ได้อย่างน่าเชื่อถือ

การทำเบนช์มาร์กเป็นหัวข้อที่ซับซ้อน และการอธิบายอย่างละเอียดครอบคลุมทั้งหมดอยู่นอกขอบเขตของหนังสือเล่มนี้ แต่ต่อไปนี้คือพื้นฐานที่ควรรู้

อย่างแรก คุณต้องมีเวิร์กโหลด (workload) ให้วัด ในอุดมคติคุณควรมีเวิร์กโหลดหลากหลายรูปแบบที่สะท้อนการใช้งานโปรแกรมจริง เวิร์กโหลดที่ใช้อินพุตจากโลกจริงนั้นดีที่สุด แต่[ไมโครเบนช์มาร์ก]และ[การทดสอบความเครียด]ก็มีประโยชน์ได้ในระดับพอเหมาะ

[ไมโครเบนช์มาร์ก]: https://stackoverflow.com/questions/2842695/what-is-microbenchmarking
[การทดสอบความเครียด]: https://en.wikipedia.org/wiki/Stress_testing_(software)

อย่างที่สอง คุณต้องมีวิธีรันเวิร์กโหลด ซึ่งจะเป็นตัวกำหนดเมตริก (metric) ที่ใช้วัดด้วย
- [เบนช์มาร์กเทสต์]ที่มีมาให้ในตัวของ Rust เป็นจุดเริ่มต้นที่ง่าย แต่ใช้ฟีเจอร์ที่ยังไม่เสถียร จึงทำงานได้เฉพาะบน Rust เวอร์ชัน nightly เท่านั้น
- [Criterion] และ [Divan] เป็นทางเลือกที่ซับซ้อนกว่า
- [Hyperfine] เป็นเครื่องมือทำเบนช์มาร์กเอนกประสงค์ที่ยอดเยี่ยม
- [Bencher] สามารถทำเบนช์มาร์กแบบต่อเนื่องบน CI รวมถึง GitHub CI ได้
- [Gungraun] ให้การผสานรวมกับ `cargo bench` พร้อมการวัดที่แม่นยำสูง
- ฮาร์เนส (harness) สำหรับทำเบนช์มาร์กแบบกำหนดเองก็เป็นไปได้เช่นกัน ตัวอย่างเช่น [rustc-perf] เป็นฮาร์เนสที่ใช้ทำเบนช์มาร์กคอมไพเลอร์ Rust

[Criterion]: https://github.com/bheisler/criterion.rs
[Divan]: https://github.com/nvzqz/divan
[Hyperfine]: https://github.com/sharkdp/hyperfine
[Bencher]: https://github.com/bencherdev/bencher
[Gungraun]: https://github.com/gungraun/gungraun
[rustc-perf]: https://github.com/rust-lang/rustc-perf/

เมื่อพูดถึงเมตริก มีตัวเลือกให้เลือกมากมาย และตัวเลือกที่เหมาะสมจะขึ้นอยู่กับลักษณะของโปรแกรมที่ทำเบนช์มาร์ก ตัวอย่างเช่น เมตริกที่สมเหตุสมผลสำหรับโปรแกรมแบบแบตช์อาจไม่เหมาะกับโปรแกรมแบบโต้ตอบ เวลาตามนาฬิกาจริง (wall-time) เป็นตัวเลือกที่ชัดเจนในหลายกรณี เพราะสอดคล้องกับสิ่งที่ผู้ใช้รับรู้ อย่างไรก็ตาม ค่านี้อาจมีความแปรปรวนสูง โดยเฉพาะอย่างยิ่ง การเปลี่ยนแปลงเล็กน้อยของการจัดวางหน่วยความจำอาจทำให้ประสิทธิภาพแกว่งไปมาอย่างมีนัยสำคัญแต่เพียงชั่วคราว ดังนั้น เมตริกอื่นที่มีความแปรปรวนต่ำกว่า (เช่น จำนวนไซเคิลหรือจำนวนคำสั่ง) อาจเป็นทางเลือกที่สมเหตุสมผลกว่า

การสรุปผลการวัดจากหลายเวิร์กโหลดก็เป็นความท้าทายเช่นกัน และมีหลายวิธีในการทำ โดยไม่มีวิธีใดดีที่สุดอย่างชัดเจน

การทำเบนช์มาร์กให้ดีเป็นเรื่องยาก อย่างไรก็ตาม อย่าเครียดเกินไปกับการตั้งระบบเบนช์มาร์กให้สมบูรณ์แบบ โดยเฉพาะเมื่อคุณเริ่มต้นเพิ่มประสิทธิภาพโปรแกรม การทำเบนช์มาร์กที่พอใช้ได้ย่อมดีกว่าการไม่ทำเลยมากนัก จงเปิดใจกว้างต่อสิ่งที่คุณกำลังวัด และเมื่อเวลาผ่านไป คุณจะปรับปรุงการทำเบนช์มาร์กให้ดีขึ้นได้เมื่อคุณเรียนรู้ลักษณะเฉพาะด้านประสิทธิภาพของโปรแกรมคุณ
