# การทำเบนช์มาร์ก

การทำเบนช์มาร์ก (benchmarking) โดยทั่วไปคือการเปรียบเทียบประสิทธิภาพของโปรแกรมตั้งแต่ 2 โปรแกรมขึ้นไปที่ทำงานอย่างเดียวกัน ในบางกรณีอาจเป็นการเปรียบเทียบระหว่างโปรแกรมคนละตัว เช่น Firefox เทียบกับ Safari และ Chrome หรือในบางกรณีอาจเป็นการเปรียบเทียบระหว่างโปรแกรมเดียวกันแต่ต่างเวอร์ชัน ซึ่งกรณีหลังนี้ช่วยให้เราตอบคำถามได้อย่างมั่นใจว่า "การแก้ไขโค้ดครั้งนี้ช่วยให้โปรแกรมเร็วขึ้นจริงหรือไม่"

การทำเบนช์มาร์กเป็นเรื่องที่มีความละเอียดซับซ้อน และการเจาะลึกทุกแง่มุมอยู่นอกเหนือขอบเขตของหนังสือเล่มนี้ แต่หลักการพื้นฐานที่สำคัญมีดังนี้:

ประการแรก คุณต้องมีเวิร์กโหลด (workload) สำหรับใช้วัดผล ในอุดมคติควรเตรียมเวิร์กโหลดที่หลากหลายและสะท้อนถึงพฤติกรรมการใช้งานจริงของโปรแกรม การใช้ข้อมูลอินพุตจากโลกจริงเป็นวิธีที่ดีที่สุด แต่การใช้ [ไมโครเบนช์มาร์ก][ไมโครเบนช์มาร์ก] และ[การทดสอบรับโหลดสูง (stress tests)][การทดสอบความเครียด] ก็มีประโยชน์เช่นกันหากใช้อย่างพอเหมาะ

[ไมโครเบนช์มาร์ก]: https://stackoverflow.com/questions/2842695/what-is-microbenchmarking
[การทดสอบความเครียด]: https://en.wikipedia.org/wiki/Stress_testing_(software)

ประการที่สอง คุณต้องมีเครื่องมือสำหรับรันเวิร์กโหลดเหล่านั้น ซึ่งจะเป็นตัวกำหนดเมตริกหรือตัวชี้วัด (metrics) ที่ใช้ด้วย
- [เบนช์มาร์กเทสต์] ที่ติดตั้งมาพร้อมกับ Rust เป็นจุดเริ่มต้นที่ง่าย แต่ยังเป็นคุณลักษณะที่ไม่เสถียร (unstable feature) จึงใช้งานได้เฉพาะบน Rust เวอร์ชัน nightly เท่านั้น
- [Criterion] และ [Divan] เป็นทางเลือกที่มีฟีเจอร์ระดับสูงและทรงพลังกว่า
- [Hyperfine] เป็นเครื่องมือเบนช์มาร์กเอนกประสงค์ที่ยอดเยี่ยมสำหรับวัดผลคำสั่งบนคอมมานด์ไลน์
- [Bencher] ช่วยทำเบนช์มาร์กอย่างต่อเนื่องบนระบบ CI รวมถึง GitHub Actions
- [Gungraun] ช่วยผสานการทำงานร่วมกับ `cargo bench` โดยให้การวัดผลที่มีความแม่นยำสูง
- เรายังสามารถสร้าง benchmarking harness ขึ้นมาใช้เองได้ด้วย ตัวอย่างเช่น [rustc-perf] ซึ่งเป็น harness ที่สร้างขึ้นมาเพื่อเบนช์มาร์กคอมไพเลอร์ Rust โดยเฉพาะ

[เบนช์มาร์กเทสต์]: https://doc.rust-lang.org/nightly/unstable-book/library-features/test.html
[Criterion]: https://github.com/bheisler/criterion.rs
[Divan]: https://github.com/nvzqz/divan
[Hyperfine]: https://github.com/sharkdp/hyperfine
[Bencher]: https://github.com/bencherdev/bencher
[Gungraun]: https://github.com/gungraun/gungraun
[rustc-perf]: https://github.com/rust-lang/rustc-perf/

ในส่วนของเมตริกวัดผลนั้นมีให้เลือกใช้หลากหลาย และการเลือกเมตริกที่ถูกต้องจะขึ้นอยู่กับธรรมชาติของโปรแกรมที่นำมาวัด เช่น เมตริกที่เหมาะสมกับโปรแกรมประมวลผลแบบแบตช์ (batch) อาจไม่ตอบโจทย์โปรแกรมเชิงโต้ตอบ (interactive) เวลาจริงที่ผ่านไป (wall-time) มักเป็นตัวเลือกแรกในหลายสถานการณ์เพราะตรงกับสิ่งที่ผู้ใช้สัมผัสได้โดยตรง อย่างไรก็ตาม ค่า wall-time อาจมีความแปรปรวน (variance) สูงมาก โดยเฉพาะอย่างยิ่ง การเปลี่ยนแปลงเพียงเล็กน้อยของการจัดวางหน่วยความจำ (memory layout) ก็อาจทำให้ประสิทธิภาพแกว่งไปมาได้อย่างมีนัยสำคัญแม้จะเกิดขึ้นเพียงชั่วคราว ดังนั้น เมตริกอื่นที่มีความแปรปรวนต่ำกว่า (เช่น จำนวนรอบสัญญาณนาฬิกา หรือจำนวนคำสั่งประมวลผล) จึงอาจเป็นทางเลือกที่เสถียรกว่า

การสรุปผลการวัดจากหลายๆ เวิร์กโหลดเข้าด้วยกันก็เป็นอีกหนึ่งความท้าทาย ซึ่งมีวิธีคิดหลายรูปแบบโดยไม่มีวิธีใดที่ดีที่สุดในทุกสถานการณ์

การทำเบนช์มาร์กที่ดีเป็นเรื่องยาก ถึงกระนั้น อย่ากังวลจนเกินไปกับการสร้างระบบเบนช์มาร์กที่สมบูรณ์แบบไร้ที่ติ โดยเฉพาะในช่วงเริ่มต้นของการปรับปรุงประสิทธิภาพ การทำเบนช์มาร์กแบบพอใช้ได้ย่อมดีกว่าการไม่ทำเลยอย่างแน่นอน ขอให้เปิดใจกว้างกับตัวเลขที่คุณกำลังวัด และเมื่อเวลาผ่านไป คุณจะค่อยๆ พัฒนาระบบเบนช์มาร์กให้แม่นยำยิ่งขึ้นได้ เมื่อเริ่มเข้าใจพฤติกรรมด้านประสิทธิภาพของโปรแกรมมากขึ้น
